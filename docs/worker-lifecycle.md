# Owned worker crash lifecycle

Managed writer and speech launches bind the actual creating process identity to a standard-library parent watcher. The native Qwen, Fish, MOSS, and experimental MLX workers start it before optional dependency imports or model loading. Their JSON-lines stdout remains reserved for the existing protocol. Parent-loss diagnostics use stderr; parent loss ends only that worker with exit code 75.

POSIX watches the actual parent relationship. Windows opens a `SYNCHRONIZE` process handle and checks the creation identity supplied by the actual launcher; the retained handle observes that process's death even if its numeric PID is reused. Isolated native runtimes require no psutil or other added dependency. Direct standalone workers without managed launch metadata watch their observed parent; managed launches always supply the creating PID and Windows creation identity.

External llama.cpp runs through the same stdlib helper in guardian mode using the existing host Python. The guardian inherits the native stdout/stderr streams, launches exactly the supplied argv without a shell, and owns the native child's process group. Parent loss, ordinary cancellation, and deadlines stop only that owned group with bounded escalation. Windows uses the existing system `taskkill /T` mechanism against the live child it created. No persisted run PID is used as authority for killing a process. Normal writer timeout behavior remains enforced by the existing caller; the guardian also has a bounded fallback deadline. Captured invocation evidence retains the original native argv plus the guardian argv, helper SHA-256, and policy.

The helper is bundled beside worker scripts in source distributions and wheel data. Workers load verified sibling bytes explicitly, which also works under isolated Python `-I`. A missing helper, symlinked helper, or managed helper-hash mismatch fails before runtime imports. Experimental MLX cache identity and durable resume provenance include a separate helper SHA-256, alongside the existing worker and adapter hashes. An adapter checks it again before launch. Historical receipts remain readable and unchanged; a receipt without helper attestation fails resume clearly rather than acquiring a new identity retroactively. Use its original frozen source or start a new run.

This change does not redesign the heavyweight slot. That slot is still held by the calling process, so a hard parent crash releases it before the watcher detects death and finishes cleanup. A small post-crash admission interval remains; these watchers do not establish strict zero-overlap admission. A watchdog thread also requires Python to receive execution time. Killing the guardian itself forcibly can bypass its cleanup. Stronger guarantees require platform-specific containment or moving lock ownership through the supervised child's entire lifetime. Existing RAM, swap, timeout, model verification, and GPU-lock policies remain in place.

Model-free lifecycle tests use temporary Python children, kill only parents owned by their fixture, check that unrelated sentinels remain alive, exercise loading/busy states and group descendants, validate Windows handle/creation behavior, and verify helper packaging and attestation. They never load model weights or invoke inference.
